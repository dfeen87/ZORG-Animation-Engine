# ADR — position-only morph extension 0.1

Status: implemented, creator artistic review pending.

The feasibility study supports useful control-position changes without new field degrees of freedom. Keep Gaussian arithmetic, weights, sigma, threshold, original scenes, fixed IDs, immutable scene objects, integrator, speed/displacement guards and live event grammar unchanged. New CLI modes and contracts isolate the extension.

`MorphRuntime` subclasses `LiveRuntime` and adds a `(N,2)` quintic-blended target-offset channel. It delegates every numerical transition to the existing `LiveRuntime.step`. Morph commands supersede the current blended shape target, preserving target-position continuity and committed position/velocity. The quintic curve has zero first/second derivative at its own endpoints; superseding a running blend can change its derivative. The spring state remains continuous, but global C2 continuity of the target under supersession is not claimed.

Each position-only recipe binds sorted element IDs, original homes, weights, sigmas and threshold via a canonical field digest. Its offsets use world half-height units relative to each original home. Home is exactly zero. Parameter changes or different identities are rejected, not silently adapted. Future signed fields, extra controls or variable field parameters require another explicit contract and feasibility study.

The existing channel biases remain additive. Before accepting a motion change, enumerate the Cartesian product of shape, translation and squash/stretch blend endpoints and the analytic wander bounding box (each component ≤0.08 world units). Quintic blends stay inside their endpoint convex hulls. The norm is convex, so corner bounds conservatively enclose all combined target offsets for all future ticks. Check both `k_i * norm(offset_i) <= max_total_force` and displacement admission. This can reject combinations that would have been safe with correlated timing. Actual per-tick force, state displacement and speed checks still apply; admission does not authorize state repair or promise arbitrary overshoot-free dynamics. The original force bound applies to external bias, consistent with Build 0.1; spring and damping arithmetic is unchanged.

Events use `cz-morph-event-0.1`, with a contiguous sequence, effective simulation tick and one strict command payload: named morph, capture, or normalized historical live motion. UI commands never enter the mathematical stream. `cz-morph-session-0.1` embeds configuration, recipes, events, snapshots, final/trajectory digests, source hashes and environment. Replay runs the same parser normalization, admission and integrator and checks every final digest and capture. Unknown versions and provenance changes fail honestly.

A capture is detached canonical data from a committed state: positions, velocities, field parameters, channels, active target, seed/config/source binding and validation. Its stable content ID includes its label and tick. PNG generation happens in offline export, keeping full-resolution raster work out of the input loop. Capture labels never become arbitrary file paths. Take/export ownership uses exclusive directory creation. All recording outputs remain under the user-chosen new take; existing takes are refused.

The shared terminal loop gains optional runtime/recorder/parser/viewport hooks; default Build 0.1 execution is unchanged. The morph adapter reuses input editing, terminal restoration, backlog handling, preview frame skipping and the exact field evaluator. Simulation stays at 60 Hz; preview runs independently on a small raster; offline export runs at 384×384, 30 FPS. No GUI or network service is introduced.

Promotion is deferred: exported captures are reconstructable curated states, not automatically accepted targets. Capture-to-recipe promotion needs an explicit review of translation/wander removal and force admission. No inference, training, semantic classifier or future ML infrastructure exists.
